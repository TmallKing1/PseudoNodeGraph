# .gil / .gia 导出格式与转写说明

记录日期：2026-11-08。来源：大富豪项目对实际导出的只读解码（`inferred`：路径由导出内容反推，未与官方 schema 核对），
社区资料作参考：script-1024/genshin-miliastra-file-format、Wu-Yijun 的 `gia.proto`（2.0.9b）。
所有工具只读，不写游戏文件；以下路径以 `read.cjs` 输出的字段号表示（`a/b/c` = 字段 a 下的字段 b 下的字段 c）。

## 1. 容器

| 文件 | 结构 |
|---|---|
| `.gil` 关卡导出 / `.gia` 资源导出 | 大端 u32：`文件长度-4`、`版本 1`、`头魔数 0x326`、`file_type`（2 = gil，3 = gia）、`载荷长度 = 文件长度-24`；载荷 `[20, 长度-4)`；末尾 u32 `尾魔数 0x679` |
| 千星沙箱调试日志 `.gia`（`Beyond_Debug_Log/*.gia`，追踪 / 日志导出） | 大端 u32：`文件长度-4`、`文件长度-8`；其后到文件末尾都是载荷 |

载荷是**无 schema 的 protobuf 线格式**。`read.cjs` 把每个长度字段同时尝试解析为子消息（`message_candidate`）与 UTF-8 文本
（`text_candidate`），定长字段保留 `float_candidate`，最后整体重编码并与原文件逐字节比较（2026-11-8 导出 5.6 MB、375 320 条消息通过）。
调试日志的可读内容直接看 `<stem>.strings.json`（每条日志前有 `编号 / 时间 / 玩家名 / 关卡名` 等条目头）。

## 2. 关卡导出（.gil）的语义路径

| 路径 | 含义 |
|---|---|
| 根字段 `10` | 节点图区 |
| `10/2/1` | 复合节点定义：接口 id = `4/1/5`，名称 = `200`，实现图 id = `4/4/5`（接口 id ≠ 内部图 id） |
| 任意深度、字段 1 为身份 `{3: kind 以 21 开头, 5: id}` 的消息 | 一张节点图：名称 `2`，节点 `3`（重复），复合端口映射 `4`（重复） |
| 节点 | `1` 序号（编辑器里的 #N）；`2/5` 节点类型码（见 `data/node-types.json`；≥ 1e9 为复合节点，等于其接口 id）；`4` 引脚（重复） |
| 引脚 | `1 = {1: 种类, 2: 序号}`；`2/2` 内核序号；`3` 值；`4` 类型码；`5` 连线（重复）`{1: 对端节点, 2: {1: 种类, 2: 序号}}` |
| 引脚种类 | 1 执行入，2 执行出，3 数据入，4 数据出，5 信号名选择引脚 |
| 值 | 101–106 标量（102 = int64，需按有符号回绕；105 = 字符串），109 = 列表（每项字段 1），110 = 包装（取 `110/2` 再解） |
| 根字段 `4` / `5` / `8` | 实体（`/1` 重复）：区 4 的组件字段为 6/7/8，区 5、8 为 5/6/7，分别存名称（组件类型 1，`11/1`）、挂载的节点图（组件类型 3，`13/1/1/2`）、编辑器定义的自定义变量（组件类型 1，`11/1`：`2` 名称、`3` 类型码、`4` 初值） |
| 根字段 `9/502` | 界面控件实体属性 |

已知缺口：
- 列表常量（如【拼装列表】）按 **100 个槽位**序列化，实际长度看数据入引脚 0 的值；未修改的默认引脚值**不保存**。
- 局内存档变量（编辑器变量面板的第二页）可能不在上述实体组件里：大富豪导出中，存档用的列表变量没有出现在 `entities.json` 的定义中，
  因此 `variable-checks.json` 的 `undefined` 只是候选（见仓库根目录 `待确认.md`）。
- 枚举引脚存**数字码**，按百位分族（600/601、700/702、1300–1307、1402–1405、1900/1901、4100–4102、5702、5800–5802 等），尚未逐一对应到 `core/enums.ts` 的选项。

### 节点身份（旧版提取 `logic-graphs.json`）

`{origin: 10001, domain: 20000, kind, id}`：`kind 22000` = 内置节点（id = 类型码），`22001` = 复合节点（id = 复合接口 id）。
`shell` 与 `kernel` 不同时（如【获取自定义变量】50 / 内核 57），表中记为 `kernelId`。

| 码 | 类型 | 码 | 类型 |
|---|---|---|---|

## 3. 工具

```bash
node tools/gil/read.cjs 关卡.gil out/            # 解码 + 逐字节校验 → out/关卡.decoded.json / .strings.json / .summary.json
node tools/gil/extract.cjs out/关卡.decoded.json  # → out/graphs.json definitions.json entities.json variable-checks.json
node tools/gil/dump.cjs out/graphs.json 1073741931 # 打印一张图：#节点 名称 [复合目标] 引脚 种类:序号=值 / ->对端
node tools/gil/lint.cjs graphs/ [--roles=r.json]   # 伪代码的编辑器规则检查（规则见文件头）
node tools/gil/build-node-types.cjs --logic=... --export=out/graphs.json --identities=...   # 重建 data/node-types.json
```

`variable-checks.json` 的 `undefined` 列出“节点图按字面名读写、但没有任何实体在编辑器里定义”的变量：这些变量在运行时动态创建，
**不会同步给客户端**，且常常是拼写错误。

## 4. 导出 → 伪代码转写（大富豪项目做法，未移植）

大富豪项目用 `transcribe.cjs` 把旧存档的 192 张图（3999 个节点）转写为 TypeScript，规则如下，可按需重做：

- 一张图一个文件 `<图id>.ts`，文件头逐行列出 `// #N 节点名`（包括未连线的查询节点），校验脚本确认每个节点都被引用。
- 每张图是工厂函数 `export function G<id>(input: {p0: () => T, ...}, flow: {p0?: () => void, ...})`：
  `nN()` = 节点 #N 的执行体；`qN_P()` = #N 数据出引脚 P 的惰性求值（每次读取都重新求值，与编辑器一致）；
  `eventInN(ev)` = 事件入口；主图另导出 `mount()` 注册 `on*` 监听。复合节点的调用方按调用位置缓存一个实例：
  `let cache4; function sub4() { return cache4 ??= G1073741829({p0: () => ..., p1: () => ...}, {}); }`，
  复合输出按端口映射读取 `sub4().q<内部节点>_<引脚>()`。新写的复合可直接用 `src/core/composite.ts` 的 `defineComposite`。
- 控制流：双分支 → `if`，多分支 → `switch`（注意出口序号 0 是默认出口，与分支值无关），有限循环 / 列表迭代循环 → `for`，
  跳出循环在导出里表现为连到循环节点“中断”入口的回边。
- 局部变量：【获取局部变量】出参 0 是句柄、出参 1 是值，转成闭包变量 + 初始化标志。
- 信号：发送节点的参数引脚按 `SignalRegistry` 的字段顺序拼成对象字面量；`SignalRegistry` 可由导出中的信号定义生成。
- 无法从导出确定的值（缺默认值、列表长度、枚举数字码）写成 `declare const G<图>_N<节点>_in<引脚>: NG.<类型>` 并加
  `/** UNRESOLVED 原因 */`，**不要**用 0 填充。
- 编辑器节点名与文档名不一致时用别名表（已并入 `data/node-types.json` 的 `docName`）。

## 5. 桌面回归框架（大富豪项目做法，未移植）

`bridge-test.cjs` / `boot-test.cjs`：用 `ts.transpileModule` 把伪代码转成 JS，在 `vm` 里对一个假的 `NG` 运行；
`sendSignal` 放进先进先出队列，启动测试同时跑“立即执行”和“排队执行”两种调度（信号时序尚未证实，见 `待确认.md`）。
它只验证规则与数据流，不能证明编辑器里的接线、负载或时序正确。
